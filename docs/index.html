#What is Sketchware Pro?

Sketchware was an app that let you build Android apps visually, with blocks, right on your phone. Development stopped years ago. Sketchware Pro is a community mod that keeps it alive, fixes what was broken and adds what the original never had.

🧩

Blocks, but real code

Design with visual blocks and Sketchware Pro generates genuine Java. Nothing is locked in a proprietary format: you can read, edit and export the code.

📱

A full IDE on Android

Layout editor, logic editor, resources, libraries, manifest, signing and compilation — all running on the device itself.

🧱

Project catalogue

Start from a template, a blank project or a shared .swb file. Everything lives in your storage and stays yours.

🔓

Community-driven

Made by the community for the community. Free, with no subscription and no telemetry of its own.

Important: this project is a mod of Sketchware. It is source-available, not open source, and it is not allowed on Google Play or any other app store. Install it by sideloading only. See the legal notice.

#Main features

What you actually get inside the app.

Visual layout editor

Drag widgets onto a canvas, edit properties, preview and generate the XML.

Logic / blocks editor

Events, conditions, loops, variables and functions — with a searchable block palette.

Code editor

Syntax highlighting, autocomplete and a file tree for the generated sources.

Java & Kotlin

Kotlin compilation is supported through the bundled kotlinc toolchain.

Library manager

Firebase, Material Components, Glide, Retrofit and many more, ready to add to your project.

On-device compiler

Builds the APK on the phone, with a bundled aapt2 per architecture.

Resource editor

Images, colors, fonts, sounds and strings without leaving the app.

Custom blocks

Create your own blocks and share them with the community.

Built-in debugger

Logcat, error reports and, in recent versions, real debugging work in progress.

#Changes in this fork

This repository is a personal fork of Sketchware Pro. Every improvement gets added here as it lands — this list is the changelog of what has been done, and the roadmap of what is still missing.

2026-09-21 · v7.0.5 build published

First versioned build done

  • Build no longer needs a git repo — git rev-parse used to run during configuration and corrupted BuildConfig.GIT_HASH. Now it reads GIT_HASH / GIT_SHORT_HASH from the environment and only uses git when .git exists.
  • SKETCHUB_API_KEY default — without the env var, BuildConfig used to contain the literal "null". It is now an empty string.
  • Release signing moved out of the repo — credentials come from RELEASE_STORE_* / RELEASE_KEY_* (environment or ~/.gradle/gradle.properties), with an explicit warning when they are missing.
  • 64 empty catch blocks annotated — 44 files were swallowing exceptions silently; they now log through Log.d("SketchwarePro", …).
  • Faster builds — org.gradle.parallel and org.gradle.caching enabled.
  • Repository published and versioned — git history, .gitignore audited, first public release with the APK attached.
2026-09-21 · size

One APK per architecture done

ABI splits enabled: assembleRelease produces one APK per architecture instead of a single universal one, so a device no longer downloads the other three sets of native libraries. Verified: each APK carries only its own lib/<abi>/, including the bundled aapt2. Published as v7.0.5.1, signed with the original key.

2026-09-21 · signing

The original signing key stays done

Release builds keep the project's own testkey.keystore (SHA-256 a40da80a…) on purpose, so new APKs install over existing installs. Verified with apksigner: all four split APKs carry that fingerprint. A private 4096-bit keystore is kept aside at ~/.android-keys/sketchware-pro/release.jks for the day a real distribution identity is wanted.

2026-09-22 · editor

Go to definition and find usages done

The editor now jumps between files: "Go to definition" and "Find usages" resolve the symbol under the cursor across all the project's sources and open the result, with a chooser when there are several matches. The symbol index records each declaration's file and line, and the navigation runs on the LSP scaffolding that was already in the repo. Version v7.0.5.7.

2026-09-22 · editor

SDK and library completions done

Suggestions now go beyond your own code: they include the Android SDK classes (android.jar) and the classes of the libraries your project uses. The simple name is inserted and the fully qualified name shows as the description. The index is read once, cached in memory and on disk, and warmed up when a .java file opens. Version v7.0.5.6.

2026-09-22 · editor

Live Java diagnostics done

Errors and warnings are now underlined as you type: 1.2 s after you stop, the app compiles just the file you are editing with the Eclipse compiler it already bundles (project classpath, files/java as source path) and shows the message when you tap the mark. Runs off the UI thread, discards stale results and fails silently. Version v7.0.5.5.

2026-09-22 · editor

Autocompletion with your own symbols done

First slice of the in-app IDE: the Java editor now suggests the classes, methods and fields of your project while you type, plus Java keywords. The index is built by reading the project's source files (no compiler), cached and refreshed only when sources change. Everything else in the editor still delegates to sora-editor's language. Version v7.0.5.4.

2026-09-21 · app

The app's GitHub links point here done

The repository, releases and commits links inside the app now open aurenox-global/Sketchware-Pro instead of upstream, so the update notice checks this fork's releases. Verified inside the built APK (resources.arsc). Version v7.0.5.3.

2026-09-21 · CI

CI is green done

Android CI and Verification Baseline pass now. The last blocker was subtle: the bundletool jar that GitHub Actions downloads ships embedded classes.dex files next to Java bytecode, and R8 refuses an archive with both — the local Gradle cache has the same version without them. Filtering that jar is unsafe (it drops aapt2-proto, and those dex files are what bundletool uses to build AABs), so CI builds with -PskipMinify while local release builds keep R8 enabled.

2026-09-21 · repo fix

The repository was incomplete done

A .gitignore bug: the pattern build/ matched any directory named build at any depth, so three real source packages — mod/hey/studios/build/, mod/jbk/build/ and mod/pranav/build/ — were never committed. Eight files were missing from the public repo, which is why every CI run failed to compile and why a fresh clone could not build. Rules are now scoped with explicit exceptions. CI also builds without secrets now (mock google-services.json + the committed public testkey), and the workflow handles ABI splits.

2026-09-21 · size

R8 code shrinking done

R8 is enabled for release builds, cutting each APK from ~129 MB to ~106 MB. It needed two dependency jars repackaged at build time (kotlinc-for-sketchware ships dalvik/**, kxml2 ships org/xmlpull/** — Android provides both), the -dontwarn rules R8 generates, and disabling the Crashlytics mapping upload (local builds use a mock google-services.json).

next · size

Resource shrinking blocked

shrinkResources would delete resources fetched by name — there are 29 getIdentifier() call sites. A res/raw/keep.xml has to be written first.

next · quality

Translations, deprecations and tests planned

  • i18n — 2,239 strings and not a single values-<language> folder.
  • Deprecated APIs — getColor() ×126, onActivityResult ×63, startActivityForResult ×47, getExternalStorageDirectory ×43.
  • Lint debt — a 24,169-line baseline that only detects drift, never shrinks.
  • God classes — LogicEditorActivity (3,031 lines), BlocksHandler (2,837 lines).
  • Storage permissions — MANAGE_EXTERNAL_STORAGE and requestLegacyExternalStorage are a problem for modern Android.

#Install

There is no store version. You install the APK yourself.

  1. Download the right APK from the releases page: app-arm64-v8a-release.apk for almost every modern phone, app-armeabi-v7a-release.apk for old 32-bit devices, x86_64/x86 for emulators.
  2. Allow installation from unknown sources for your browser or file manager (Android will ask you when you open the file).
  3. Open the APK and install. The signing key is unchanged, so it installs over previous builds.
  4. Optional: install over ADB, which also keeps your data.
adb install -r app-arm64-v8a-release.apk
Requirements: Android 8.0 (API 26) or newer. An ARM64 device is recommended — the bundled compiler and toolchain work best there.

#Build it yourself

From source to APK. Takes a while the first time, then it is quick.

  • JDK 17 — java -version should report 17.x.
  • Android SDK — platform 36 and build-tools 35 installed; point local.properties at it (sdk.dir=/path/to/android-sdk).
  • Google Services file — app/google-services.json is optional; the build scripts create a temporary placeholder from app/src/debug/google-services.json if needed.
# debug build
./gradlew :app:assembleDebug

# release build (signed)
./gradlew :app:assembleRelease

# or use the helper scripts
./compile_project.command
./compile_release.command
Signing warning. If RELEASE_STORE_FILE, RELEASE_STORE_PASSWORD, RELEASE_KEY_ALIAS and RELEASE_KEY_PASSWORD are not set, the build falls back to the repository's bundled testkey.keystore — a public AOSP test key. The resulting APK is fine for local testing, but anyone could sign an update that Android would accept as yours. Never publish an APK signed with it.

#FAQ

Is it free?

Yes. No subscription, no ads, no payment of any kind. The upstream project accepts support through Patreon only to keep development going.

Can I publish it on Google Play?

No. Sketchware Pro is a mod of Sketchware and publishing it — original or modified — on any app store is explicitly not allowed.

Does it need a computer?

No. The whole IDE and the compiler run on the phone. A computer is only useful for building this repository from source.

Are the apps I make mine?

Yes. Sketchware Pro generates plain Android sources and resources, and the APKs you build belong to you. What is not yours is Sketchware Pro's own code.

Why is the APK so large?

It bundles the on-device compiler, four aapt2 binaries, an Android jar, library archives and a Kotlin toolchain. ABI splits already cut it from 141 MB to about 129 MB per device; code and resource shrinking are still on the roadmap.

Why does the release use a test key?

On purpose: it is the original signing identity, so updates install over existing builds. It is a public key, so treat these APKs as sideload/testing builds and switch to the private keystore only if you accept a full reinstall.
