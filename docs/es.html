#¿Qué es Sketchware Pro?

Sketchware era una app que permitía crear aplicaciones Android de forma visual, con bloques, directamente en el teléfono. El desarrollo se detuvo hace años. Sketchware Pro es un mod de la comunidad que lo mantiene vivo, arregla lo que estaba roto y añade lo que el original nunca tuvo.

🧩

Bloques, pero código real

Diseña con bloques visuales y Sketchware Pro genera Java de verdad. Nada queda encerrado en un formato propietario: puedes leer, editar y exportar el código.

📱

Un IDE completo en Android

Editor de layouts, editor de lógica, recursos, librerías, manifest, firma y compilación — todo corriendo en el propio dispositivo.

🧱

Catálogo de proyectos

Empieza desde una plantilla, un proyecto en blanco o un archivo .swb compartido. Todo vive en tu almacenamiento y es tuyo.

🔓

Hecho por la comunidad

De la comunidad para la comunidad. Gratis, sin suscripciones y sin telemetría propia.

Importante: este proyecto es un mod de Sketchware. Es source-available, no open source, y no está permitido en Google Play ni en ninguna otra tienda. Se instala por sideload. Ver el aviso legal.

#Características principales

Lo que encontrarás dentro de la app.

Editor visual de layouts

Arrastra widgets al lienzo, edita propiedades, previsualiza y genera el XML.

Editor de lógica (bloques)

Eventos, condiciones, bucles, variables y funciones, con paleta de bloques con buscador.

Editor de código

Resaltado de sintaxis, autocompletado y árbol de archivos de las fuentes generadas.

Java y Kotlin

La compilación de Kotlin está soportada mediante el kotlinc incluido.

Gestor de librerías

Firebase, Material Components, Glide, Retrofit y muchas más, listas para añadir.

Compilador en el dispositivo

Genera el APK en el teléfono, con aapt2 por arquitectura incluido.

Editor de recursos

Imágenes, colores, fuentes, sonidos y textos sin salir de la app.

Bloques personalizados

Crea tus propios bloques y compártelos con la comunidad.

Depurador integrado

Logcat, informes de error y, en versiones recientes, depuración real en desarrollo.

#Cambios de este fork

Este repositorio es un fork personal de Sketchware Pro. Cada mejora se va añadiendo aquí según se implementa: esta lista es el registro de lo hecho y la hoja de ruta de lo que falta.

2026-09-21 · build v7.0.5 publicado

Primera versión versionada hecho

  • La build ya no necesita un repo git — git rev-parse se ejecutaba al configurar y ensuciaba BuildConfig.GIT_HASH. Ahora lee GIT_HASH / GIT_SHORT_HASH del entorno y solo usa git si existe .git.
  • Default de SKETCHUB_API_KEY — sin la variable de entorno, BuildConfig contenía el literal "null". Ahora es cadena vacía.
  • Firma del release fuera del repositorio — las credenciales salen de RELEASE_STORE_* / RELEASE_KEY_* (entorno o ~/.gradle/gradle.properties), con aviso explícito si faltan.
  • 64 bloques catch vacíos anotados — 44 archivos se tragaban las excepciones en silencio; ahora registran con Log.d("SketchwarePro", …).
  • Builds más rápidas — activados org.gradle.parallel y org.gradle.caching.
  • Repositorio publicado y versionado — historial git, .gitignore auditado y primera release pública con el APK adjunto.
2026-09-21 · tamaño

Un APK por arquitectura hecho

ABI splits activados: assembleRelease genera un APK por arquitectura en lugar de uno universal, así que el dispositivo deja de descargar los otros tres juegos de librerías nativas. Verificado: cada APK lleva solo su propio lib/<abi>/, incluido el aapt2 incluido. Publicado como v7.0.5.1, firmado con la clave original.

2026-09-21 · firma

Se mantiene la clave de firma original hecho

El build de release conserva la testkey.keystore del propio proyecto (SHA-256 a40da80a…) a propósito, para que los APK nuevos se instalen encima de los existentes. Verificado con apksigner: los cuatro APK por arquitectura llevan esa huella. La keystore privada de 4096 bits queda guardada en ~/.android-keys/sketchware-pro/release.jks para el día en que se quiera una identidad de distribución real.

2026-09-22 · editor

Completado del SDK y de las librerias hecho

Las sugerencias ya no se limitan a tu codigo: incluyen las clases del SDK de Android (android.jar) y las de las librerias que usa tu proyecto. Se inserta el nombre simple y en la descripcion va el nombre completo. El indice se lee una vez, se cachea en memoria y en disco, y se precalienta al abrir un .java. Version v7.0.5.6.

2026-09-22 · editor

Diagnosticos de Java en vivo hecho

Los errores y avisos se subrayan mientras escribes: 1,2 s despues de parar, la app compila solo el fichero que editas con el compilador de Eclipse que ya lleva dentro (classpath del proyecto y files/java como sourcepath) y muestra el mensaje al tocar la marca. Corre fuera del hilo de la interfaz, descarta resultados obsoletos y falla en silencio. Version v7.0.5.5.

2026-09-22 · editor

Autocompletado con tus propios simbolos hecho

Primera pieza del IDE dentro de la app: el editor de Java sugiere ahora las clases, metodos y campos de tu proyecto mientras escribes, ademas de las palabras clave. El indice se construye leyendo las fuentes del proyecto (sin compilador), cacheado y refrescado solo cuando cambian. El resto del editor sigue delegando en sora-editor. Version v7.0.5.4.

2026-09-21 · app

Los enlaces de GitHub de la app apuntan aquí hecho

Los enlaces del repositorio, de releases y de commits dentro de la app abren ahora aurenox-global/Sketchware-Pro en vez del upstream, así que el aviso de actualizaciones consulta las releases de este fork. Verificado dentro del APK compilado (resources.arsc). Versión v7.0.5.3.

2026-09-21 · CI

El CI está en verde hecho

Android CI y Verification Baseline ya pasan. El último bloqueo era sutil: el jar de bundletool que descarga GitHub Actions incluye ficheros classes.dex embebidos junto al bytecode, y R8 rechaza un archive con ambos — la caché local tiene esa misma versión sin ellos. Filtrarlo no es seguro (se pierde aapt2-proto y esos dex son los que bundletool usa para construir AABs), así que el CI compila con -PskipMinify y el build local de release mantiene R8 activo.

2026-09-21 · repo fix

El repositorio estaba incompleto hecho

Un fallo del .gitignore: el patrón build/ coincidía con cualquier carpeta llamada build a cualquier profundidad, así que tres paquetes de código fuente reales — mod/hey/studios/build/, mod/jbk/build/ y mod/pranav/build/ — nunca se subieron. Faltaban ocho ficheros del repo público, y por eso el CI no compilaba y un clon limpio tampoco podía compilar. Las reglas están ahora acotadas con excepciones explícitas. Además el CI ya compila sin secretos (google-services.json mock + la testkey pública subida) y el workflow soporta los ABI splits.

2026-09-21 · tamaño

Reducción de código con R8 hecho

R8 activado en el build de release: cada APK baja de ~129 MB a ~106 MB. Hicieron falta dos jars reempaquetados en tiempo de build (kotlinc-for-sketchware trae dalvik/**, kxml2 trae org/xmlpull/** — Android ya aporta ambos), las reglas -dontwarn que R8 genera, y desactivar la subida del mapping a Crashlytics (el build local usa un google-services.json mock).

siguiente · tamaño

Reducción de recursos bloqueado

shrinkResources borraría recursos que se obtienen por nombre — hay 29 usos de getIdentifier(). Antes hay que escribir un res/raw/keep.xml.

siguiente · calidad

Traducciones, deprecaciones y tests planificado

  • i18n — 2.239 strings y ni una sola carpeta values-<idioma>.
  • APIs deprecadas — getColor() ×126, onActivityResult ×63, startActivityForResult ×47, getExternalStorageDirectory ×43.
  • Deuda de lint — un baseline de 24.169 líneas que solo detecta drift, nunca reduce.
  • God classes — LogicEditorActivity (3.031 líneas), BlocksHandler (2.837 líneas).
  • Permisos de almacenamiento — MANAGE_EXTERNAL_STORAGE y requestLegacyExternalStorage son un problema en Android moderno.

#Instalar

No hay versión en tiendas. El APK lo instalas tú.

  1. Descarga el APK que corresponda desde la página de releases: app-arm64-v8a-release.apk para casi todos los móviles modernos, app-armeabi-v7a-release.apk para dispositivos antiguos de 32 bits, x86_64/x86 para emuladores.
  2. Permite instalar desde orígenes desconocidos para tu navegador o gestor de archivos (Android te lo pedirá al abrir el archivo).
  3. Abre el APK e instala. La clave de firma no cambia, así que se instala encima de versiones anteriores.
  4. Opcional: instala por ADB, que además conserva tus datos.
adb install -r app-arm64-v8a-release.apk
Requisitos: Android 8.0 (API 26) o superior. Se recomienda un dispositivo ARM64 — el compilador y el toolchain incluidos funcionan mejor ahí.

#Compílalo tú mismo

Del código al APK. La primera vez tarda, después es rápido.

  • JDK 17 — java -version debe reportar 17.x.
  • Android SDK — plataforma 36 y build-tools 35 instalados; apunta local.properties a él (sdk.dir=/ruta/al/android-sdk).
  • Google Services — app/google-services.json es opcional; los scripts crean un placeholder temporal desde app/src/debug/google-services.json si hace falta.
# build de debug
./gradlew :app:assembleDebug

# build de release (firmado)
./gradlew :app:assembleRelease

# o usa los scripts de ayuda
./compile_project.command
./compile_release.command
Aviso de firma. Si no defines RELEASE_STORE_FILE, RELEASE_STORE_PASSWORD, RELEASE_KEY_ALIAS y RELEASE_KEY_PASSWORD, la build cae a la testkey.keystore incluida en el repositorio — una clave de test pública de AOSP. El APK sirve para pruebas locales, pero cualquiera podría firmar una actualización que Android aceptaría como tuya. Nunca publiques un APK firmado con ella.

#Preguntas frecuentes

¿Es gratis?

Sí. Sin suscripción, sin anuncios y sin pagos. El proyecto upstream acepta apoyo por Patreon solo para mantener el desarrollo.

¿Puedo publicarlo en Google Play?

No. Sketchware Pro es un mod de Sketchware y publicarlo — original o modificado — en cualquier tienda está expresamente prohibido.

¿Necesita ordenador?

No. Todo el IDE y el compilador funcionan en el teléfono. El ordenador solo hace falta para compilar este repositorio desde el código.

¿Las apps que hago son mías?

Sí. Sketchware Pro genera fuentes y recursos Android estándar, y los APK que compilas son tuyos. Lo que no es tuyo es el código de Sketchware Pro.

¿Por qué el APK pesa tanto?

Incluye el compilador en el dispositivo, cuatro binarios aapt2, un jar de Android, archivos de librerías y el toolchain de Kotlin. Los ABI splits ya lo bajaron de 141 MB a unos 129 MB por dispositivo; la reducción de código y recursos sigue en la hoja de ruta.

¿Por qué la release usa una test key?

A propósito: es la identidad de firma original, así las actualizaciones se instalan encima de lo que ya tengas. Al ser una clave pública, trátalos como builds de sideload y prueba, y cambia a la keystore privada solo si aceptas reinstalar desde cero.

#Aviso legal

Sketchware Pro no es open source. Es source-available: puedes leer el código y enviar cambios, pero no es tuyo. Parte del código puede infringir el copyright de Sketchware.
